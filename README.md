## 1. Overview
This pipeline performs a controlled comparison between short-read and long-read DNA embeddings. It investigates how read length affects the quality of DNA sequence embeddings generated by DNABERT-S. Specifically, we examine whether the model can better distinguish sequences from different species in embedding space when using long reads versus short reads. All steps of anaylsis are orchastrated in a nextflow pipeline. It downloads reference genomes, processes them, simulates sequencing reads, computes DNA embeddings using DNABERT-S, performs clustering, and generates evaluation and visualisation outputs.

**Key steps of the pipeline:**
-	download reference genomes form NCBI by accession number
-	simulates short reads (InSilicoSeq) and long reads (Badreads)
-	convert FASTQ files to labeled TSV format
-	generate DNA embeddings using DNABERTS
-	perform k-means clustering and evaluate with statistical metrics such as ARI, NMI and Completeness
-	visualizes clustering results (t-SNE + distance analysis)

**Supported execution environments:**
- **Local** — for development and testing (`-profile test`)
- **HPC** — on the LiSC cluster via SLURM (`-profile lisc`)
The SLURM job script generates a batch job to execute the full pipeline on an HPC cluster.

Short-read and long-read branches run in **parallel** through a shared named subworkflow (`process_read_pipeline`). The pipeline is managed by Nextflow and fully configured through `nextflow.config`.

## 2. Pipeline Architecture
The pipeline is implemented as a Nextflow workflow. Read simulation is performed directly with shell/bash commands inside Nextflow processes. All downstream analysis steps call individual Python scripts. Short and long reads are processed in parallel by passing both channels into the shared subworkflow `process_read_pipeline`.

| Process | Script / Tool | Description |
|---|---|---|
| `download_fasta` | `download_genome.py` | Download genome FASTA files from NCBI by accession ID |
| `process_fasta` | `process_genomes.py` | Standardize genomes moves raw files, rewrites headers, creates processed single FASTAs, writes header CSV, and builds a combined multi-fasta  |
| `calculate_coverage_for_short_reads` | `genome_coverage_calculator.py` | Compute the number of reads for short-read simulation based on target coverage and read length |
| `short_reads` | InSilicoSeq (`iss`) | Simulate short reads with iss generate |
| `long_reads` | Badread | Simulate Nanopore long reads with badread with the correct target coverage |
| `converting_reads_format` | `fastq_to_tsv.py` | Convert FASTQ to two-column TSV: sequence + genome label |
| `get_n_lines_of_tsv` | bash `head` | Truncate TSV to first N lines for fast testing (only when `use_get_n_lines = true`) |
| `calculate_embeddings` | `calculate_embedding_for_tsv_02.py` | Compute DNABERT-S embeddings; output raw `.npy`, standardised `.npy`, and labels |
| `kmeans_clustering` | `cluster_embeddings.py` | k-means clustering (5 seeds); report ARI, NMI, Purity, Completeness |
| `visualization_embeddings` | `visualize_embeddings.py` | t-SNE scatter plot: true labels, predicted clusters |
| `cluster_distance_calculations` | `distances_within_between_cluster.py` | Compute within-cluster and between-cluster distances  |
| `cluster_distance_visualization` | `compare_distances.py` | Violin + heatmap plot comparing short vs. long read distances |

## 5.	Input data
The pipeline requires a single **tab-separated** input file containing NCBI accession IDs and relative abundances. The file path is set via the `input_txt` parameter (see [Section 7](#7-parameters)).

**Columns:**
- `Accession_ID` — NCBI genome accession number (e.g. `GCF_000025985.1`)
- `Abundance` — relative frequency in the simulated community. Values range between 0 and 1; all entries must sum to exactly 1.0.

**Example:**
```text
Accession_ID Abundance
GCF_000025985.1 0.4
GCF_049532935.1 0.2
GCF_025147765.1 0.15
GCF_009731575.1 0.08
GCF_000196555.1	0.05
GCF_029024925.1 0.06
GCF_001953955.1 0.04
GCF_900537995.1 0.02
```


## 6. Running the Pipeline
The --double-dash syntax overrides any params.* value. A -single-dash (like -profile) controls Nextflow itself, not pipeline parameters.

### 6.1.    Local Execution (for testing and development)
The `test` profile sets reduced defaults (`target_coverage = 1`, fewer reads) and runs all processes locally without SLURM.
```shell
nextflow run final_pipeline.nf -profile test
```
#### 6.1.1 Resume a Previous Run
Nextflow caches completed process outputs. Use `-resume` to skip steps that have not changed since the last run.
```shell
nextflow run final_pipeline.nf -profile test -resume
```
### 6.2 	 HPC Execution (LiSC)
The make_slurm_job.sh script generates a SLURM batch job that executes the full Nextflow pipeline. Run from the scripts/ directory:
```shell
bash scripts/make_slurm_job.sh
# Submit to SLURM
sbatch slurm_scripts/slurm_SWE_nextflow_pipeline.job
```
The following variables at the top of `make_slurm_job.sh` control the SLURM job that runs the Nextflow **head process** (not individual pipeline steps):

| Variable | Default | Description |
|---|---|---|
| `Job_name` | `SWE_nextflow_pipeline` | SLURM job name — used in log filenames and email notifications |
| `cpus` | `4` | CPUs for the Nextflow head process |
| `memory` | `8GB` | Memory for the Nextflow head process |
| `time` | `2-00:00:00` | Maximum wall-clock time for the whole job (2 days) |
### 6.5     Overriding default parameters
All parameters are defined in nextflow.config inside the params { } block and can be overridden at runtime via the command line. The --double-dash syntax overrides any params.* value. 
```shell
# Override one parameter
nextflow run parallized_pipeline.nf --dataset_name "my_run"

# Override multiple parameters
nextflow run parallized_pipeline.nf \
  --dataset_name "my_run" \
  --target_coverage 20 \
  --model_short "HiSeq"
```
##   7. Parameters
All parameters are defined in `nextflow.config` inside the `params { }` block.

### 7.1 General
| Parameter | Default | Description |
|---|---|---|
| `dataset_name` | `"test"` | Name of the dataset/run. Used as prefix in output filenames and folder names |
| `data_dir_name` | `"results"` | Top-level output folder name, one level above `projectDir` |
| `output_base` | `"${projectDir.parent}/${data_dir_name}"` | Full base path for all pipeline outputs. Derived automatically from `data_dir_name` |
| `input_txt` | `"${projectDir.parent}/data/input/input.txt"` | Path to the tab-separated input file with accession IDs and abundances |

### 7.2 Short Read Simulation (InSilicoSeq)

| Parameter | Default | Description |
|---|---|---|
| `target_coverage` | `10` | Target sequencing coverage (×). Used by the coverage calculator to determine the number of reads |
| `seeds_sim` | `42` | Random seed for InSilicoSeq to ensures reproducible short-read simulation |
| `short_read_length` | `300` | Read length in bp for simulated short reads |
| `model_short` | `"MiSeq"` | InSilicoSeq error model. Options: `MiSeq`, `HiSeq`, `NovaSeq` |

### 7.3 Long Read Simulation (Badread)

| Parameter | Default | Description |
|---|---|---|
| `mean_length_long` | `15000` | Mean read length in bp |
| `length_stdev_long` | `13000` | Standard deviation of read length in bp. High value reflects realistic Nanopore variability |
| `identity` | `"95,99,2.5"` | Read identity as `min,max,mean` in percent — models per-read accuracy against the reference |
| `error_model` | `"nanopore2023"` | Badread error profile. Options: `nanopore2023`, `pacbio2016`, `random` |
| `seed_long` | `42` | Random seed for Badread for reproducible long-read simulation |

### 7.4 DNABERT-S

| Parameter | Default | Description |
|---|---|---|
| `test_model_dir` | `"${projectDir.parent}/DNABERT-S"` | Path to the local DNABERT-S model directory |
| `data_dir` | `"."` | Working data directory passed to the embedding script via `--data_dir` |

### 7.5 Testing

| Parameter | Default | Description |
|---|---|---|
| `use_get_n_lines` | `true` | When `true`, truncates each TSV to `n_lines_test` rows before embedding, enables fast end-to-end testing. Set to `false` in the `lisc` profile for production runs |
| `n_lines_test` | `10` | Number of reads to keep per TSV when `use_get_n_lines` is `true`. The `test` profile sets this to `2000` |

### 7.6 Python Script Paths

These parameters point to the Python scripts called by each process. All default to `${projectDir}/<filename>` and rarely need to be changed.

| Parameter | Default script |
|---|---|
| `py_coverage_calc` | `genome_coverage_calculator.py` |
| `py_fastq_to_tsv` | `fastq_to_tsv.py` |
| `py_embedding_calc` | `calculate_embedding_for_tsv_02.py` |
| `py_kmeans` | `cluster_embeddings.py` |
| `py_visualization` | `visualize_embeddings.py` |
| `py_download` | `download_genome.py` |
| `py_process_fna` | `process_genomes.py` |
| `py_cluster_dist` | `distances_within_between_cluster.py` |
| `py_visualization_cluster_dist` | `compare_distances.py` |

6.2     Output files Reference

| Extension | Description |
|---|---|
| `.fna` | FASTA genome files — individual per accession (raw and processed) and as a combined multi-FASTA used for read simulation |
| `.fastq` | Simulated reads — one combined file per read type.  |
| `*.tsv` | Reads in tabular format with two columns: `sequence` and `bin_id` (true genome accession label) |
| `*_emb.npy` | Raw embedding matrix (shape: N_reads × embedding_dim) |
| `*_emb_stand.npy` | Standardised embedding matrix (StandardScaler, zero mean and unit variance) |
| `*_labels.txt` | True genome labels, one per line, aligned row-by-row with the embedding matrix |
| `*_kmeans_results.csv` | True and predicted labels per read, using the best-performing k-means seed (highest ARI) |
| `*_kmeans_results_metrics.txt` | Clustering evaluation metrics summary: ARI, NMI, Purity, Completeness — best seed and mean across all seeds |
| `*.png` | t-SNE scatter plots with three panels: true labels, predicted clusters, and correct vs. incorrect per read |
| `*_${read_type}_cluster_distances.npz` | NumPy archive with per-read centroid distances (`distances`), pairwise inter-cluster distance matrix (`between`), and labels (`true_label`) |
| `cluster_comparison.png` | Combined distance comparison: violin plots and heatmaps for short vs. long reads side by side |
| `.html` / `.txt` | Nextflow execution reports in `pipeline_info/`: resource usage (`report.html`), process timing (`timeline.html`), raw process statistics (`trace.txt`) |


## 9. Pipeline Resources

Default resource allocations apply to all processes unless overridden with `withName`. Only the embedding process requires a GPU.

| Process | CPUs | Memory | Time | Notes |
|---|---|---|---|---|
| All processes (default) | 4 | 4 GB | 2h | Base defaults; applies when no profile is active |
| All processes (`lisc`) | 6 | 16 GB | 5h | SLURM; applies to all steps unless overridden below |
| `calculate_embeddings` (`lisc`) | 6 | 32 GB | 12h | Requests 1 GPU via `--gres=gpu:1` |

To change resource limits without editing the pipeline, add overrides in `nextflow.config` using the `withName: 'process_name' { }` selector inside a `process { }` block.
